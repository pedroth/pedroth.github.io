I started this experiment in rendering pixels to the screen because I notice that we are losing digital sovereignty(the ability to own and control our digital environment).

From my perspective, setting a simple color on the screen should be something easy. However, I feel it complicated, requiring the developer to jump through many hoops of modern graphics APIs.

Fortunately, there is a countercurrent to this trend in independent projects such as Serenum OS, the famous TempleOS, Pico-8, and many Linux-based operating systems.

To take back some control, I want to build a simple software shader capable of drawing directly to the screen without relying on any graphics API. To achieve this, I used the Linux framebuffer, which provides a relatively direct way to manipulate pixels. It is not perfect, but it is close enough to the level of control I wanted to explore.

Building a software shader from scratch

A shader can be defined as a function that takes pixel coordinates and returns a color.

shader:(i,j)→color

Color in this article will be defined as a tuple from (red,green,blue)∈[0,1]3 . Usually color is represented as a 32-bit integer, where each byte (8 bits) represents the intensity of red, green, blue, and alpha channels (R, G, B, A). But you can think of any other representation of color that you like.

The screen is a grid of pixels indexed by coordinates (i,j), where i∈{0,...,H−1} is the row, j∈{0,...,W−1} is the column, and the origin (0,0) is at the top-left corner.

To apply the shader, we iterate over every pixel and evaluate the shader at each coordinate.

simple_shader(i, j):
    return (i / (H-1), j / (W-1), 0)  # (red, green, blue)

for i in {0, ..., H-1}:
    for j in {0, ..., W-1}:
        color = simple_shader(i, j)
        set_pixel(i, j, color)

To make it more interesting, I suggest making a coordinate change from (i,j)→(x,y), where the coordinates start from the corner left of the screen and x∈0,...,W−1 and y∈0,...,H−1. These are the more natural coordinates to work with and are commonly used in graphics programming. 

simple_shader(x, y):
    return (x / (W-1), y / (H-1), 0)

for i in {0, ..., H-1}:
    for j in {0, ..., W-1}:
        x = j
        y = H - 1 - i
        color = simple_shader(x, y)
        set_pixel(i, j, color)

This is very cool and all, but the computer does not actually store a grid of pixels, instead, it stores a contiguous block of memory.

To solve this issue, we need to iterate over the memory instead of pixel coordinates. But for that we need a way to calculate the corresponding pixel coordinates from the memory index. Let's see a simple example:

As the image above suggests, j index the columns and we need to jump W columns for each row i. So we can calculate the memory address as k=i⋅W+j. For a generic case, check the image below:

Now to compute the pixel coordinates from the memory address, we must reverse the formula. It seems impossible, because we have one equation (for k) and two unknowns (i and j). But we can note the following statement from regular arithmetic:

N,d,q,r∈N,N=q⋅d+r,q=⌊dN​⌋,r=Nmodd,0≤r<d

Where N is the number we want to divide, d is the divisor, q is the quotient, and r is the remainder. By pattern matching the formula k=i⋅W+j with the statement above, we can find the solution for i and j:

N=q⋅d+r⇔k=i⋅W+j

Hence:

i=⌊Wk​⌋,j=kmodW

Putting everything together, we can render the shader to the screen with the following code:

simple_shader(x, y):
    return (x / (W-1), y / (H-1), 0)

for k in {0, ..., W*H-1}:
    i = k % W
    j = floor(k / W)
    x = j
    y = H - 1 - i
    color = simple_shader(x, y)
    screen_memory[k] = color

To make things even more interesting, we can add a time variable to the shader, which will allow us to create animations. The demo animation above is generated by the following shader:

simple_shader(x, y, t):
    r = ((x / (W-1)) * t) % 1
    g = ((y / (H-1)) * t) % 1
    return (r, g, 0)

old_time = measure_time_in_seconds()
time = 0
while time < 10:
    current_time = measure_time_in_seconds()
    dt = current_time - old_time
    old_time = current_time
    time += dt
    for k in {0, ..., W*H-1}:
        i = k % W
        j = floor(k / W)
        x = j
        y = H - 1 - i
        color = simple_shader(x, y, time)
        screen_memory[k] = color
